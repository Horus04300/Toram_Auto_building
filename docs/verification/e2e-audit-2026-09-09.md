# 2026-09-09 E2E 점검

대상: 소스 0.6.4를 `npm run desktop:prepare`로 생성한 dist, Windows의 headless Edge, 격리 브라우저 컨텍스트. 확인한 3건을 수정했고 최종 E2E 15/15가 통과했다.

## 재현된 문제

### 해결: 빈 슬롯 잠금의 추천·적용 계약 불일치

1. 장비에서 비어 있는 무기 슬롯 1을 잠근다.
2. 결과 → 요구조건의 제한을 모두 해제하고 결과 탭에서 빠른 추천을 생성한다.
3. 활성화된 추천 적용 버튼을 누른다.
4. `잠긴 크리스타 슬롯이 비어 있습니다. 잠금을 해제하거나 값을 입력해 주세요.` 경고가 뜨고 다른 슬롯에도 추천이 적용되지 않는다.

초기 감사에서는 컴파일러가 빈 잠금을 null로 받아들이지만 적용기가 예외로 거부했다. 사용자는 잠긴 빈 슬롯은 연산 전후 동일하므로 복사가 필요 없다는 의도를 확인했다. 적용기는 빈 잠금에 쓰기·이벤트를 하지 않고 다른 슬롯만 적용하도록 수정했다. 잠금 용량을 초과한 추천은 여전히 전체 적용 전에 거부한다.

수정 후 `node tools/test-d4-recommendation-apply.mjs` 통과(값 있는 잠금, 빈 잠금, 전체 빈 잠금, 잘못된 슬롯 용량의 원자적 거부). 실제 Edge E2E의 빈 잠금 적용도 통과했다.

### 해결: 빠른 추천 실패 시 내부 코드만 표시

초기 감사에서는 새 브라우저 컨텍스트의 기본 입력으로 결과 탭을 열면 `NO_FEASIBLE_GREEDY_BUILD`만 표시됐다. 요구조건을 모두 해제하면 추천이 생성됐다.

`assets/js/optimizer.js`의 결과 표시에서 빠른 추천 실패를 한국어 안내로 변환했다. 정밀 계산 또는 요구조건·잠금·추천 제외 조정을 제안하며 가능한 조합이 없다고 확정된 것은 아니라는 의미를 명시한다. 기타 메시지 없는 실패에도 내부 코드 대신 설정 확인과 재계산을 안내한다. 탐색 상태와 계산식은 변경하지 않았다.

### 해결: 실패 후 이전 추천 옵션 개수 잔존

1. 요구조건을 해제하여 정상 추천을 표시한다. 이번 입력에서는 `적용 옵션 18개`였다.
2. 요구조건의 HP를 999999999로 설정하고 결과 탭을 다시 누른다.
3. `NO_FEASIBLE_GREEDY_BUILD`와 `추천 불가`가 표시되지만, `전체 추천 옵션 보기 · 적용 옵션 18개`가 남는다.

초기 실패 분기는 옵션 개수를 초기화하지 않아 이전 성공 결과의 메타데이터가 남았다. 이전 크리스타 이름 전체가 남는다고 판정한 것은 아니다. 수정 후 실패/취소 시 상세 영역을 숨기고 개수·크리스타 상세·옵션 태그·효율 데이터의 추천 결과 참조를 비운다. 유효한 추천을 다시 만들면 상세 영역을 표시한다. E2E에서 실패 후 정리와 성공 후 재표시를 확인했고 `dist/e2e-audit/failed-preview.png`를 시각 확인했다.

- `npm run desktop:prepare`: 통과, dist 0.6.4.
- 초기 감사의 `npm run test:r0`: 묶음 출력 69/69. 실제 실행 68개 통과, native 저장 E2E 1개는 `TORAM_E2E_CDP` 미설정으로 SKIP. 이번 표시 수정 후 전체 묶음은 반복하지 않았다.
- 초기 감사의 `node tools/verify-update-browser.mjs`: 통과. Native 설치 API는 mock. 이번 표시 수정 후 재실행하지 않았다.
- `node tools/audit-browser-e2e.mjs`: 초기 12/15 → 빈 잠금 수정 후 13/15 → 표시 수정 후 최종 15/15 통과, 종료 코드 0.
- `node tools/test-d4-native-resume-ui-n5.mjs`, `node tools/test-d4-recommendation-apply.mjs`: 수정 후 통과.
- 주요 통과: 6개 탭, 레벨·타겟·장비·잠금 복원, 10종 무기 전환, 요구조건 취소·저장, JSON 내보내기/파일 가져오기, 스킬 투자·콤보 저장, 거리 override 상호 배타, 레벨 상한과 저장값 일치, 잠금 해제 후 추천 적용, 8슬롯 고정 실제 Worker exact 실행.
- 이번 브라우저 실행에서 수집된 uncaught exception 및 로컬 HTTP 4xx/5xx는 없음.

## 재실행

`CODEX_PLAYWRIGHT_PATH`에 설치된 Playwright 모듈 경로를 지정하고 `npm run desktop:prepare` 후 `node tools/audit-browser-e2e.mjs`를 실행한다. Edge가 설치되어 있어야 한다. 기존 도구와 같은 외부 런타임 사용 방식이며 의존성 설치나 사용자 브라우저 프로필 변경은 하지 않는다.

JSON 결과와 실패 스크린샷은 `dist/e2e-audit/`에 생성된다. dist는 git 제외 산출물이다. 테스트의 성공은 해당 흐름에 한정하며 모든 조합의 게임 수식이나 성능을 증명하지 않는다.

## 미실행 경계

이 브라우저 감사에서는 실제 Tauri 저장·Native 제어·설치를 실행하지 않았다. 후속 실제 저장·재시작·Native pause/resume 등 통합 8/8 통과는 `desktop-e2e-2026-09-09.md`에 별도 기록했다. 설치/업그레이드/제거, Rust 전체 단위 테스트와 전체 후보 성능 P95는 여전히 이번 작업에서 미실행이다. 보류된 전투 피격 시뮬레이션과 콤보 후속 기능은 결함으로 분류하거나 구현하지 않았다.
