# 크리스타 공동 공급량 묶음 검토

- 확인: 2026-10-11, Native solver v19. 모든 계산 가능한 묶음을 [공통 상한](crysta-joint-supply-bound.md)에 연결했다. 경계의 외향 완화는 실제 공급량의 정확한 압축과 구분한다.
- 전수 범위: 크리스타 425개, 기본/조건부 옵션 행 483개, 정규화된 원본 키 87개. StatRegistry 계산/유틸리티 키 52개와 Native 좌표 52개를 모두 분류했다.
- 실제 후보 확인: `crysta-saved-sword-shield-revenir-unlocked.json`의 입력을 그대로 compiler와 Pareto 준비에 전달했다. 컴파일 패키지 14,973개, 준비 후 6,251개다. 이 입력의 패키지 수·옵션 출현은 다른 무기/잠금의 성능 근거가 아니다.
- 재현: `node tools/verification/audit-crysta-joint-supply.mjs`. 키별 분류·출현·사례·소스 해시는 `crysta-joint-supply-inventory.json`에 있다.

## 1. 여기서 묶음의 의미

탐색에서 선택하는 후보는 장비별 **합법적인 2슬롯 패키지**다. 한 크리스타에 두 옵션이 함께 없더라도, 같은 부위의 서로 다른 크리스타를 합친 패키지에는 함께 있을 수 있다. 각 패키지의 실제 옵션 벡터에서 공동 공급량을 계산해야 한다.

예를 들어 방향 가중치가 고정된 `a*ATKP+b*ATK+c*PHYS_PIERCE`의 최댓값을 구하면, 서로 다른 패키지의 세 독립 최댓값을 합친 것보다 관계를 잘 보존한다. 다만 그 방향을 대미지 상한으로 변환하는 안전성은 계산식별로 별도 증명이 필요하다. 실제 후보 한 개의 대미지를 미완성 조합 전체의 상한으로 쓰면 안 된다.

가산·비율 쌍은 기초값 B가 고정일 때 `floor(B*(100+p)/100)+f`를 공동 좌표 `B*p+100*f`로 다룰 수 있다. 정수 f, 정확한 비율 산술, 합산 후 내림을 전제로 한다. 기초값까지 후보 때문에 변하거나 f가 소수이면 같은 등식으로 임의 축약하지 않는다. 소수/큰 값은 안전한 외향 완화와 기존 fallback이 필요하다.

후보별로 기여량을 내림한 뒤 합하면 원식과 달라질 수 있다. **옵션 합산 → 원식의 위치에서 내림 → 상한/포화** 순서를 유지한다. 음수 옵션과 누락 키의 0도 공동 벡터에 보존한다.

## 3. 같은 계산 결과를 만드는 확장 묶음

다음 묶음도 각 패키지에서 공급한 관계를 보존할 수 있다. 여러 행에 같은 키가 등장하는 것은 의도된 의존성이다. 각 묶음을 독립 소비 자원처럼 처리해 같은 옵션을 중복 차감하지 않는다.

| 결과/묶음 | 함께 보존할 옵션 | 한 숫자로 축약할 수 없는 주요 경계 |
| --- | --- | --- |
| **물리 raw 대미지** | **ATKP + ATK + PHYS_PIERCE** | ATK는 내성을 거치고 관통은 방어력 차감 쪽에 작용한다. 관통 후 방어력 0, raw 최저 1, 단계별 내림. 따라서 동일 단위 단순 합산 대신 고정 입력의 계수/구간별 상한 |
| **마법 raw 대미지** | **MATKP + MATK + MAG_PIERCE** | 마법 내성·MDEF·방어 무시/절반 무시·공격력 선택 모드별로 계수와 분기 분리 |
| 최종 ATK/MATK의 기초값 | 위 공격 묶음 + WATKP/WATK + 무기별 STR/DEX/AGI/INT 쌍 | 기초 공격력 자체가 변하면 `% × 기초값`의 교차항. 무기별 스탯 계수와 내림, 컨버전 유지 |
| ATK+MATK 복합 공격 | ATKP/ATK + MATKP/MATK + 공통 무기/스탯 공급 | `sum`, `higher`, `atk`, `wizardBlend`의 합/최댓값/가중합 분기. 물리 공격이 항상 ATK만 읽는다고 가정 금지 |
| 듀얼소드 공격력 | ATKP/ATK + WATKP/WATK + STR/AGI/DEX 쌍 + STABILITY | 주·보조 공격력의 서로 다른 내림, 보조 안정률 곱과 100 상한. 같은 무기%의 두 무기 기여를 보존 |
| 기대 치명타 배율 | CRITP/CRIT + CDMGP/CDMG + STR/AGI 쌍; 마법 분기에는 INT 쌍도 연결 | `확률 × 크뎀`, 확률 포화, 크뎀 감쇠, 확정/고정/비치명, 마법 반영 및 STR↔INT 분기. v18 평타 CRIT 목표 좌표만으로 이 전체 묶음 완료 아님 |
| 안정률 배율 | STABILITY + 무기별 STR/DEX 쌍 | 물리 안정률 100 상한, 마법 `floor(50+물리안정률/2)`, 듀얼 보조 안정률에도 재사용 |
| HP 요구조건 | VITP/VIT + MAXHPP/MAXHP | VIT→기초 HP→HP%의 곱과 내림·포화. VIT가 변하면 HP 쌍의 B가 상수 아님 |
| MP 요구조건 | INTP/INT + MAXMP | INT→MP의 1/10 내림. 목표 MP 2,000/2,300과 raw MP 구분 |
| **AMPR 요구조건** | **INTP/INT + MAXMP + AMPR** | MP 2,000 포화→100 MP당 AMPR 계단→고정 패시브/활성 프로필. **AMPRP는 사용자 정책으로 목표에서 제외**; 각 후보의 MP 기여를 미리 내림하면 안 됨 |
| **ASPD/행동속도 요구조건** | **ASPD_P/ASPD + MOTIONSPEED + 무기별 STR/INT/AGI/DEX 쌍** | ASPD 1,000 경계, 초과분 180당 행동속도 1, 행동속도 50 상한. 1,000 미만은 행동속도로 치환 불가 |
| 발도 raw + 발도 배율 | UNSHEATHE + UNSHEATHEP + 적용 공격력/관통 묶음 | flat 발도는 내성 적용 뒤 raw에 가산, % 발도는 후단 곱. 발도 비활성 시 쌍의 목적 기여 제외 |
| 발도→ATK 변환 | UNSHEATHEP/UNSHEATHE + ATKP/ATK + WATKP/WATK | 활성 변환은 %를 ATK%와 기본 무기 ATK에, flat을 ATK+에 이동한다. 변환된 원래 발도량은 0, 변환 순서와 후보별 내림 금지 |
| 거리 배율 | SRW + LRW | 고정 거리는 사용 거리만, `useHigherRangeDamage`는 `max(SRW,LRW)`. 둘을 더하지 않음 |
| 최종 대미지 배율 | 위 raw·치명타·안정률·발도 + 사용 거리 + ELEM_P + DAMAGE_P + total 스탯 기반 스킬 계수 | 각 배율은 서로 곱해지고 단계마다 내림. `%끼리`라는 이유로 SRW/ELEM_P/DAMAGE_P를 더하거나 각 최대의 곱을 실제 후보 공급량으로 오인하지 않음 |
| CSPD/영창 감소 | AGIP/AGI + DEXP/DEX + CSPD_P/CSPD + CAST_RED | 1,000 기준 CSPD 변환 및 영창 감소 100 상한. **JS/Native 표시 파생 평가·상한을 지원하며 대미지/5개 목표는 유지** |

스킬 계수는 `skillStats`의 `totalSTR/INT/VIT/AGI/DEX`를 읽을 때만 해당 후보 공급량과 연결된다. 순수 기본 스탯 `STR/INT/...`를 읽는 항은 고정 입력이다. 모든 5개 스탯이 모든 무기에서 ATK·ASPD 등에 기여한다고 가정하지 않는다.

속성에 유리의 INT 보너스는 현재 식에서 **intBase**를 읽는다. 따라서 INTP/INT 후보를 그 보너스와 묶어 추가 대미지를 주면 안 된다.

## 4. 서로 다른 요구조건/공격 옵션 사이의 공동 공급

동일 최종 스탯을 만드는 묶음만으로 전체 관계가 끝나지 않는다. HP·MP·AMPR·평타 CRIT·ASPD/행동속도와 목적 대미지를 동시에 공급하는 패키지도 공동 벡터로 보존해야 한다. HP를 채우는 후보가 공격력을 깎거나, CRIT과 공격력을 함께 제공하는 경우가 여기에 해당한다.

v19는 전체 MP→AMPR, ASPD→행동속도, HP의 기초값 의존성과 5개 목표/대미지 공동 방향을 지원한다. 포화·단계별 내림·조건의 외향 완화 때문에 상자가 느슨해질 수 있지만 실제 해를 잘라내지 않는다. ASPD 목표가 1,000 이하이면 행동속도가 충족 여부를 바꾸지 않으며, 초과 목표에서는 MOTIONSPEED를 준비 단계의 관련 좌표로 보존한다.

가능한 공동 공급 부분집합은 매우 많다. 이번 목록은 계산 결과별 전체 가족과 연결선을 식별한 것이며, 모든 부분집합의 고차원 상한을 동시에 계산하자는 뜻은 아니다. 입력에서 변하는 좌표와 유효 제약만 선택하고, 트리의 자식 공간에서도 지지값이 유지되도록 설계해야 한다.

## 5. 실제 데이터에서 확인한 사례/제외 항목

- 물리 3개 옵션이 함께 살아 있는 준비 패키지: `special:돈예티+오르고 노바2`는 ATKP 5, ATK 100, PHYS_PIERCE 5; `special:십이지 축복+오르고 노바2`는 ATKP 5, ATK 10, PHYS_PIERCE 5다.
- CRIT/CRITP를 한 원본 행에서 함께 제공: 아놀드·아놀드2·호뢰파섬 각 15/15. HP 쌍은 크리스탈 타이탄의 MAXHPP 10/MAXHP 1,000이 확인된다.
- 이 실제 물리 입력에서 마법 3옵션 모두가 0이 아닌 패키지는 0개다. 마법 묶음 불필요나 마법 입력 성능 판정의 근거가 아니다. 서로 다른 공급자 사이의 상충도 공동 상한의 대상이다.
- 원본 87키 중 36키는 registry 계산/유틸리티, 51키는 `notModeled`, 미등록 키는 0이다. Native 52좌표 중 원본에 없는 16키도 구현했다: VIT/ELEM_P/DAMAGE_P/CAST_RED, ATK_UP/MATK_UP 10키, 속성 플래그 2키. 이들의 합성 검증을 현재 데이터의 성능 이득으로 계산하지 않는다.
- ATK_UP_STR/DEX/INT/AGI/VIT와 MATK_UP의 10개 계열은 **순수 기본 스탯**에 비례하는 공급이다. Native 후보 읽기·평가·공통 상한에 연결하고 JS parity를 검증했다. 최종 스탯에 비례하는 옵션으로 바꾸지 않는다.
- ELEM_AWAKENING/MAGIC_ELEMENT는 기본 플래그와 후보의 양수 공급으로 켜지는 분기다. Native 평가와 외향 상한에 연결했다. 분기 경계를 넘는 상자는 양쪽 가능성을 포함한다.
- AMPR%+AMPR+는 raw 화면 수치에는 함께 적용되지만, 현재 최적화 목표에서는 AMPR%를 제외한다. 해당 정책을 이번 검토로 되돌리지 않는다.
- DEF/DEFP, MDEF/MDEFP, ACC/ACCP, FLEE/FLEEP, HP_REGEN/HP_REGENP, MP_REGEN/MP_REGENP 등의 %·+ 계열은 현재 대미지/5개 요구조건의 계산에 연결되지 않는다. `notModeled` 보존 키 전체는 JSON의 `keyAudit`에 분류했다. 이들을 가지치기 근거로 사용하지 않는다.
- CSPD/영창·행동속도 표시가 있다고 추천 점수를 DPS로 바꾸지 않는다. 현재 목적은 고정된 선택 공격의 기대 대미지다.

## 6. 적용 범위와 검증
