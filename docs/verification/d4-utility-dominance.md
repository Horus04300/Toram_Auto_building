# 유틸리티 때문에 남는 후보: 하위호환 감사

- 날짜: 2026-09-14~15. 사용자 요청으로 이 방향은 보류했다. 현재 제품 후보 축소 정책은 변경하지 않았다.
- 사용자에게 후보 로그가 없어 실제 사례를 특정하기 어려웠다. 후보 ID·대체 후보 ID·걸린 요구조건·도달 가능한 잔여 raw 스탯을 기록하는 감사 경로를 추가했다.
- 이전 signed envelope/분기 캐시 변경은 그대로 보존했다.

## 구현한 감사

`prepareProblem(..., {enableUtilityDominanceAudit:true})`는 기존 Pareto 이후 추가 축소를 실험한다. 기본값은 꺼짐이다. Native·Worker 제품 경로에서 자동 실행하지 않는다.

같은 장비의 완성 패키지끼리 비교한다. 목적함수 좌표가 열등하지 않고 ID가 앞서는 대체 패키지만 증명 대상으로 삼는다. 각 유틸리티에 대해 다른 그룹이 실제로 공급할 수 있는 raw 스탯 합계를 열거하고, 기존 계산기로 요구조건 충족의 함의(기존 후보가 충족하면 대체 후보도 충족)를 검사한다. MAXMP는 MP와 AMPR 요구조건을 모두 통과해야 한다. HP%·INT·AMPR%·공속%·기본 스탯 의존성도 합계에 포함하며 수치를 잔여 요구량으로 잘라내지 않는다. CRIT는 목적함수 좌표로 유지한다.

raw 합계가 4,096개를 넘으면 유틸리티 후보 트리의 하한·상한으로 같은 함의를 분할 검증한다. 개별 요구조건 반례는 전체 요구조건을 만족하는 조합이 아닐 수 있으므로, 공동 제약의 하한·상한 검사를 추가로 시도한다. 모든 하위 공간을 증명한 경우만 삭제하며, 예산 초과는 후보 보존이다. 알려지지 않은 활성 변환·명시적 유틸리티 의존성 override·부호가 뒤집힌 퍼센트 구간은 감사 자체를 생략한다.

이는 현재 D4 기대 대미지 평가기의 의존성에 맞춘 감사다. 사용자 정의 목적함수/새 유틸리티 의존 계산기용 범용 Pareto 규칙이 아니다. 평가기의 의존성이 바뀌면 정책과 Gate를 재검토해야 한다.

`metadata.utilityDominanceAudit`에는 정책 버전, 평가·비교 수, 그룹별 상태 수/후보 수, 삭제 witness, 보존 사례 최대 20개를 남긴다. 기록의 `reachable-requirement-counterexample`은 해당 유틸리티의 직접 대체 반례다. 그것만으로 원래 후보가 최적해에 필요하다고 결론 내리지 않는다.

## 실측과 채택 판단

환경: Ryzen 7 9800X3D, Windows, Node v24.17.0. 입력은 `tools/fixtures/d4-native-runtime-26min-revenir.json`의 resolvedExecutionContext(현재 크리스타·잠금·금지 목록 포함), 현재 crysta-data를 사용했다.

- 기존 Pareto 이후 패키지: 무기 1,141 / 방어구 1,017 / 추가 871 / 특수 1,121 = 4,150개.
- 확대 감사: 평가 500,000회, 비교 2,173,651회, 추가 삭제 **0개**.
- 감사 36,541ms, Pareto 포함 준비 37,824.843ms. 한 번의 비용 측정이며 P95나 성능 개선 결과가 아니다.
- 기록: [원시 감사 로그](d4-utility-dominance-audit.json).
- 최적해 하한과 후보 고정 공간의 전체 상한을 비교하는 초기 실험도 기본 물리 fixture에서 추가 삭제 0개였다. 그 구현은 제거했다.

예: `고블린 형님+누토레스`를 `고블린 형님+광폭 짐승화 리그시`로 바꾸면, 잔여 MAXMP=-200인 도달 가능한 공급에서 MP 2,000 충족 여부가 달라진다. `고블린 형님+데포미스`와 `고블린 형님+네오 마기 피레시아` 비교에는 AMPR 조건 반례가 기록됐다. 각 스탯 투영 반례와 전체 빌드의 최적성은 구분해야 한다.

이 입력에서 축소 이득을 얻지 못하고 준비 비용만 늘었으므로 기본 경로로 승격하지 않았다. **제품의 하위호환 제거 성능이 개선됐다고 주장하지 않는다.** 이 기록은 같은 실패 가설을 반복하지 않기 위한 근거이며, 이후 분기에서 다른 슬롯이 좁혀진 조건부 후보 삭제를 검토할 때도 새 Gate가 필요하다.

재현(PowerShell):

```powershell
$env:D4_UTILITY_DOMINANCE_AUDIT='1'
$env:D4_P6_REVENIR='1'
$env:D4_PROOF_ONLY='1'
$env:D4_PROOF_EVALUATIONS='500000'
$env:D4_PROOF_NODES='4096'
$env:D4_PROOF_COMPARISONS='2000000'
$env:D4_PROOF_REPORT='docs/verification/d4-utility-dominance-audit.json'
node tools/benchmark-d4-native-p6.mjs
```

## 검증

- `node tools/test-d4-global-optimizer-stage2.mjs`: PASS. 축소 전후 exhaustive 점수·ID, 유틸리티가 작아도 실제 요구조건을 바꾸는 경우, 불가능 문제, 물리·마법·발도·듀얼 20개 결정적 입력×3가지 검사 예산, 상태 수/노드/평가 예산 초과 시 보존, 활성 변환 생략 검사 추가.
- 큰 실제 fixture에서는 추가 축소가 없어 최적값 변화나 성능 개선을 주장하지 않는다. Native 설치본·WebView E2E 및 배포는 실행하지 않았다.
