## 1. 범위와 판정 원칙

이 문서는 코드가 멈추거나, 오류를 내거나, 실제 선택과 다른 값을 정상 결과처럼 표시하는 경로를 기록한다. 피격·시간 경과·대상 AI·통상 공격 자동 진행처럼 사용자가 보류한 전투 상태 시뮬레이션은 결함으로 재분류하지 않는다.

상태는 다음처럼 구분한다.

- `해결`: 원문이나 기존 계약만으로 의도가 명확해 코드와 회귀 테스트를 반영함
- `해결 준비`: 원문 추가 대조가 필요하지만 제품 방향 선택은 필요하지 않음
- `결정 필요`: 어느 동작이 제품의 주 사용 방식인지에 따라 구현이 달라짐

## 3. 추가 확인 결과

### QA-P01 대미지 배율 계열

- 동일 계열 증가분은 합산하고 서로 다른 계열의 최종 배율은 곱한다.
- 조건 없이 모든 공격에 적용되는 액티브 스킬 대미지 증가는 `activeGlobalDamage` 한 계열로 처리한다.
- 예: 한손검 오라 블레이드 20%, 브레이브 오라 20%, 방패 +15 나이트 플레지 15%는 `1 + .2 + .2 + .15 = 1.55배`다.
- 장인의 검술처럼 블레이드 스킬만 대상으로 하는 패시브와 강타처럼 별도 확률 판정을 가진 전역 패시브는 서로 다른 계열이므로 곱연산한다.
- `나이트 스탠스` 표기는 사용자 확인에 따라 `나이트 플레지`의 오타로 확정했다.
- 강타·집중은 확정 배율에 섞지 않는다. 결과 탭은 `미적용 기본 대미지`, 확정 계산값에 발동 배율을 곱한 `발동 시 대미지`, `기본 × (1 + 확률 × (발동 배율 - 1))`인 `확률 반영 기대 대미지`를 모두 제공한다.
- 빌드 최적화 점수는 확률 반영 기대 대미지를 사용한다. 강타·집중 Lv.10은 각 물리·마법 공격에 10% 확률 1.2배이므로 기대 배율은 1.02배다.

### QA-P02 데이터 감사 함수

- 이 기능은 사용자가 쓰는 계산 기능이 아니라 개발자가 새 스킬 데이터를 잘못 등록했는지 검사하는 자동 점검이다.
- 예를 들어 카탈로그에 없는 ID, 알 수 없는 스킬 종류, 출처 누락, 배열 형식 오류, 계산 규칙이 전혀 없는 정의를 테스트 단계에서 검출한다.
- 기본 정의와 보강 정의가 같은 ID를 쓰는 것은 오류로 막지 않고 `shadowedDefinitions` 진단 목록에 기록한다.
- 배포 화면에는 경고를 띄우지 않으며 `test-skill-data-audit.mjs`에서 오류가 있으면 개발 테스트를 실패시킨다.

### QA-P03 내성·안정률

- 물리·마법·해당 속성·탄환 등 그 공격에 적용되는 같은 적용군의 내성 성분은 합산한다.
- 원문대로 최종 배율은 `1 - 내성/100`이며, 이 배율은 `ATK + 플레이어 레벨 - 적 레벨`에만 먼저 적용한다.
- 발도공격(+), 스킬 상수, 관통 후 방어력은 내성 계산 뒤 괄호 안에서 더하거나 뺀다.
- 피격 패턴과 속성·탄환 UI는 추가하지 않았다. `calculateResistanceProfile()`이 성분 배열·원합계·최종 배율을 내부 데이터로 보존한다.
- 음수 안정률은 정상 빌드에서 발생하지 않는 남용 입력으로 보며 별도 보정하지 않는다.

## 4. 프로그램 방향 결정이 필요한 항목

### D1. 적용된 공격이 없는 결과 탭의 동작

현재는 물리·근거리·계수 1·상수 1000이라는 가상 공격을 계산한다.

1. **명시적 적용 필수**: 공격을 적용하기 전에는 결과·최적화를 중단한다. 잘못된 정상 결과를 가장 강하게 방지한다.
2. **현재 선택 자동 적용**: 결과 탭을 열 때 콤보에서 현재 선택한 첫 타격을 자동 적용한다. 사용은 편하지만 탭 선택 상태가 계산 계약이 된다.
3. **마지막 적용 공격 저장**: 적용 타격을 세팅 JSON/localStorage에 저장한다. 저장 세팅의 재현성은 높지만, 스킬 데이터 업데이트 뒤 오래된 계수가 남을 수 있다.

권장 의도는 `1번`이다. 계산기의 최적화 결과가 무엇을 대상으로 했는지 항상 명시적으로 유지한다.

### D2. 다단·복수 타격 스킬의 결과 단위

현재 결과 탭은 선택한 한 타격의 1회 대미지만 계산한다.

1. **스킬 총합 중심**: 타수와 모든 공격 항목을 합산해 총 기대 대미지를 최적화한다. 실제 빌드 비교 목적에 가장 가깝다.
2. **선택 타격 중심 유지**: 현재처럼 특정 타격 하나를 분석한다. 후속타·도트·특수타를 따로 비교하기 쉽다.
3. **총합/선택 전환 제공**: 두 결과를 모두 제공하고 최적화 기준을 사용자가 고른다. 표현력은 높지만 UI·저장 상태가 늘어난다.

권장 의도는 `3번`이며 기본값은 총합이다.

### D3. 타격 플래그를 결과 계산에 연결하는 방식

현재 프로필에는 관통 보너스, 고정 크리티컬, 크리티컬 불가, DEF/MDEF 무시, ATK+MATK, 높은 공격력 선택, 거리·속성 예외 등이 있지만 결과 계산기로 전달되지 않는다.

1. **고빈도 플래그 우선 연결**: 관통·크리티컬·방어 무시부터 개별 추가한다. 빠르지만 미지원 플래그가 계속 남는다.
2. **공통 공격 판정 어댑터 구축**: 프로필의 타격 객체 전체를 계산기가 해석하도록 단일 계약을 만든다. 초기 작업은 크지만 새 스킬의 누락 가능성이 가장 낮다.
3. **스킬별 계산 함수 사용**: 특수 스킬마다 별도 계산기를 둔다. 복잡한 스킬은 빠르게 맞출 수 있지만 유지보수와 최적화 일관성이 낮다.

권장 의도는 `2번`이다. 이 프로그램의 핵심이 스킬 시뮬레이션과 빌드 최적화이므로 데이터와 결과 계산 사이의 손실을 구조적으로 없앤다.

### D4. 크리스타 최적화의 정확도와 반응성

현재는 약 5만 개 이상의 쌍을 UI 스레드에서 계산하고, 부위별 1위를 독립적으로 고른 뒤 합친다.

1. **현재 근사 방식 유지**: 화면 멈춤만 Worker로 옮기고 결과를 `부위별 근사 추천`으로 명시한다. 가장 빠르지만 전역 최적값을 보장하지 않는다.
2. **전체 조합 완전 탐색**: 모든 부위 조합을 계산한다. 정확하지만 조합 수와 실행 시간이 크게 증가한다.
3. **Worker 기반 후보 축소 후 전역 탐색**: 부위별 Top-K를 만든 뒤 조합을 전역 평가하고 필요 시 K를 확장한다. 속도와 정확도의 균형이 좋지만 구현과 검증이 더 복잡하다.

권장 의도는 `3번`이다. 결과에는 탐색 범위와 완전 탐색 여부를 함께 표시한다.

### D5. 마법 크리티컬·약점 속성 상태의 소유권

현재 마법 크리티컬은 약점 보정을 사실상 항상 포함하고, 무속성 지팡이 분기는 설정되지 않은 값을 검사한다.

1. **타겟/공격 상태를 명시 입력**: 공격 속성과 타겟 약점 일치 여부를 결과 대상에 포함한다. 정확하고 검증 가능하지만 입력이 늘어난다.
2. **스킬·장비에서 전부 자동 추론**: 속성 각성·마력 속성·스킬 고유 속성으로 결정하고 불명확하면 약점 아님으로 처리한다. UI는 단순하지만 조건부 속성 선택을 표현하기 어렵다.
3. **두 시나리오 동시 계산**: 약점 일치/불일치 결과를 나란히 표시한다. 입력은 적지만 최적화 결과가 두 세트가 된다.

권장 의도는 `2번`을 기본으로 하되 자동 판정이 불가능한 스킬에서만 최소 입력을 노출하는 혼합 방식이다.

### D6. 잘못된 크리스타 이름의 처리

1. **즉시 원복**: 목록에 없는 이름은 입력을 지운다. 계산 상태는 안전하지만 오타 원인을 확인하기 어렵다.
2. **인라인 오류 후 계산 차단**: 입력은 남기되 해당 슬롯과 결과 탭에 오류를 표시한다. 사용자가 무엇이 잘못됐는지 가장 명확하다.
3. **가장 가까운 이름 자동 교정**: 입력 편의는 높지만 비슷한 이름을 잘못 장착할 위험이 있다.

권장 의도는 `2번`이다.

## 6. D 섹터 사용자 결정과 현재 상태

- D1: 평타 기본 계수 1·상수 0과 결과 최상단 기준 문구를 구현했다. 선택 타격은 스킬 이름을 표시한다.
- D2: 선택 타격 중심을 유지하고 다단 타수를 최적화 점수에 곱하지 않는다. 중독 가능 스킬 습득 시에만 지정 공식의 중독 1회 피해를 내부 계산하며 배치는 보류했다.
- D3: 2번을 채택했다. 콤보 적용 타격의 전체 프로필·실행 플래그를 공통 어댑터로 전달하고 주요 대미지 판정을 한곳에서 해석한다.
- D4: 사용자는 상한 계산 기반 전역 탐색과 기회비용 반영을 요구했으나, 추가 계획 수립 전 구현을 미루도록 지시했다. 현재 코드는 기존 부위별 독립 탐색이다.
- D5: 2번을 채택했다. 속성 각성과 스킬 고유 약점 속성만 약점 공격으로 자동 판정하며 마력 속성은 약점 25%를 만들지 않는다. 스펠 버스트는 레벨 비례, 쇠약 +50%는 지팡이·메인 마도구 또는 기타 무기의 약점 공격 조건으로 적용한다.
- D6: 사용자가 말한 대상은 직접 입력한 잘못된 크리스타 이름이 맞다. 2번을 채택해 입력 보존·인라인 오류·결과 차단을 구현했다.

D4 재개 전 확정할 항목:

1. 모든 비선형·상한·조건부 스탯에서도 안전한 낙관 상한의 정의

4. 잠금·추천 제외·동일/상하위 계보 충돌을 전역 후보 제약에 포함하는 방법
