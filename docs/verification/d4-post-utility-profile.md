# 유틸리티 상한 적용 후 병목

2026-09-24. 현재 Native/checkpoint v6, utility policy 2의 제품 소스를 복사한 control/profile 바이너리로 측정했다. 이번 작업은 분석이며 제품 알고리즘은 변경하지 않았다.

## 방법과 재현

이전 계측의 준비된 루브닐·듀얼·utility-tight 입력을 사용하되 현재 평가 규칙으로 다시 실행했다. 그룹별 패키지는 각각 1141/1017/871/1121, 992/890/718/931, 445/448/446/449다. 16작업자, 입력당 control/profile 각각 새 프로세스 2회, 총 12회 순차 실행했다. 실행 중 빌드·회귀 테스트는 병행하지 않았다. 후보 준비·앱 UI/IPC는 측정 범위 밖이다.

```powershell
node tools/profile-d4-slow-inputs.mjs build
$env:D4_PROFILE_FIXTURES='revenir,dual,utility-tight'
$env:D4_PROFILE_THREADS='16'
$env:D4_PROFILE_REPEATS='2'
$env:D4_PROFILE_BUDGET='120000'
$env:D4_PROFILE_REPORT='post-utility-complete.json'
node tools/profile-d4-slow-inputs.mjs run
node tools/summarize-d4-post-utility-profile.mjs
```

이번 실행은 직전 작업에서 현재 소스로 빌드한 바이너리를 사용했으며 소스 해시 일치를 재검사했다. 진행 snapshot은 두 바이너리 모두에 포함한다. evaluator/boxStats는 1024회 중 1회 시간 표본, 나머지 구간은 전체 시간을 측정한다. 자세한 측정 한계는 `d4-slow-input-profile.md`와 동일하다. 스레드 합산 시간은 벽시계 시간이 아니며 중첩 구간끼리 합산하지 않는다. 반복 2회는 P95 성능 인증이 아니다.

Native 준비는 루브닐 약 46ms, 듀얼 약 55~57ms, 충돌 약 9~13ms(profile)다. 이번 입력에서는 초기 개별 가능성 검사가 주 병목이라는 근거가 없다.

작업자 내부 시간의 추정 합에서 evaluator는 루브닐 22.7~22.8초, 듀얼 80.4~83.1초, 충돌 21.3~22.7초다. boxStats는 각각 8.4~8.9초, 9.2~9.4초, 3.9초다. 평가 비용은 특히 듀얼에서 크다. poolRun에는 실제 계산과 기다림이 모두 포함되므로 이를 채널 잠금 비용이라고 부르지 않는다.

이전 policy의 계측과 직접 개선율을 계산하지 않는다. 특히 합성 ASPD 목표 1143은 현재 규칙에서 지연 제거/행동속도 0%p 구간으로 바뀌었으며, MP 기여 AMPR 포화도 추천 가능 공간에 영향을 준다.

첫 실험의 Gate는 소형 완전 탐색 점수·동점 ID, 부분공간 coverage, 음수 옵션·변환 의존성, 세 입력의 반복 완료 시간·메모리다. 단순 스레드 증가는 현재 관측으로 우선 추천하지 않는다.

## 별도 발견: 진행 상한 계약 문제

12회 최종 결과는 모두 exact였고 입력별 점수·최적 ID·최종 upper가 일치했다. 그러나 충돌 입력 4회에서 마지막 진행 snapshot의 `upperBound < score`를 재현했다. 예: control 1회 약 5.01초에 score 43247, upperBound 42404.

`NativeSearchSession::result()`가 heap의 남은 공간 상한을 우선 반환하고 기존 feasible 점수와 최댓값을 취하지 않는 것이 코드상 원인이다. 이는 남은 공간 상한과 전체 문제 상한을 구별하지 않은 반환 문제다. 이번 자료에서 최종 최적해가 틀렸다는 증거는 없지만, 진행 인증 상한 검사는 실패했다. 성능 개선과 별도로 반환 상한을 incumbent 이상으로 보장하는 수정과 snapshot/재개 회귀가 필요하다. 이 분석 작업에서 제품 코드는 수정하지 않았다.

집계기는 이 결함을 숨기지 않고 `certificateIssues` 4건을 원시 값으로 보존한다. `max(score, upperBound)`가 최종 exact 점수를 포함하는지도 별도 검사했다. 최종 일치는 독립 전체 완전 탐색 증명을 대체하지 않는다.
