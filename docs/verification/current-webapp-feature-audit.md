# 현재 웹 앱 기능·예외·UI 감사

> 감사일: 2026-09-04  
> 대상: 웹 UI, 계산 조립, D4 JS/Rust 경로, 세팅 저장  
> 범위 제외: 사용자가 보류한 전투 피격/시간 상태 시뮬레이션과 고급 콤보 후속 구현

구조와 데이터 흐름은 `docs/architecture/current-webapp-feature-map.md`를 먼저 본다. 이 문서는 현재 코드를 기능별로 따라가며 의도와 다른 동작 가능성, 예외 처리, 사용자 자율성, UI 노출 상태를 기록한다.

## 0. 2026-09-04 조치 결과

이 문서의 최초 감사 이후 사용자가 지정한 우선 항목을 다음과 같이 해결했다. 아래 A-01~A-04 본문은 문제 발견 당시의 근거를 보존한 기록이다.

| 항목 | 상태 | 반영 내용 |
|---|---|---|
| A-01 | 해결 | 결과 탭은 Greedy 초기해만 표시하고, branch-and-bound는 `정밀 계산 시작` 버튼으로만 실행 |
| A-02 | 해결 | 스킬 렌더와 투자 변경 commit을 분리하여 트리 탐색·증감 단위·resize가 적용 타격을 해제하지 않음 |
| A-03 | 해결 | 결과 탭 `요구조건` 모달에서 HP/MP/AMPR/평타 크리/ASPD를 조건별 활성화·수정 |
| A-04 | 해결 | 추천 제외 목록을 거리·요구조건과 함께 `ScenarioContext.optimizationPreferences`에 저장·복원 |

추가로 콤보 화면에 상호 배타적인 근거리/원거리 체크박스를 두었다. 둘 다 해제하면 선택한 스킬 타격의 기본 거리 판정을 따르며, override는 계산 프로필 적용 뒤 최종 거리로 반영된다.

## 1. 결론

현재 앱은 동일 계산식 기반 평가, 8슬롯 전역 최적화, native/Worker 대체 실행, 정확해·제한시간 해·보장 오차 표시, 잠금 슬롯 보존, 안전한 저장 경로 같은 핵심 기반이 잘 분리되어 있고 회귀 테스트도 강하다.

최초 감사에서 결과 의미와 재현성에 직접 영향을 주는 아래 네 항목을 우선 수정 대상으로 판정했으며, 현재는 위 조치 표와 같이 해결됐다.

1. 결과 탭 열기와 30초 최적화 실행이 결합되어 있다.
2. 스킬 화면의 단순 재렌더가 “투자 변경” 이벤트를 발생시켜 콤보 계산 기준을 해제하고 자동 저장을 유발한다.
3. 생존·유틸리티 요구조건이 고정 기본값으로 적용되지만 UI에서 보거나 바꿀 수 없다.
4. 추천 제외 크리스타 목록이 저장 문서에 포함되지 않아 같은 세팅을 다시 열어도 같은 후보 공간을 재현하지 못한다.

## 2. 판정 표기

| 우선순위 | 의미 |
|---|---|
| P1 | 계산 실행 의미, 결과 재현성, 사용자의 명시적 선택을 훼손할 수 있어 먼저 수정 |
| P2 | 오류 가능성·접근성·설명 부족으로 실제 사용을 어렵게 함 |

근거 표기는 `재현`(실제 배포 UI에서 확인), `코드`(정적 흐름 확인), `테스트`(자동 검증 통과)로 구분한다.

## 3. 우선 발견사항

### A-01 · 결과 보기와 최적화 실행이 같은 동작임 — P1 · 재현/코드

- `tabs.js:51`은 결과 탭 클릭 때마다 `toram:calculate`를 발생시킨다.
- 원래 `index.html:143`에 있던 명시적 계산 버튼은 `tabs.js:103`에서 제거된다.
- 실제 UI에서 결과 탭을 누르자 즉시 “전역 후보를 축약하고 있습니다”와 취소 버튼이 나타났다.
- 사용자는 이전 결과만 다시 보거나, 현재 계산 상세만 갱신하거나, 최적화를 실행할지 구분할 수 없다.

**재구성:** 결과 탭은 탐색만 담당하게 하고 `현재 세팅 계산`과 `크리스타 최적화`를 분리한다. 입력이 바뀌면 결과 상단에 “이 결과는 이전 입력 기준”을 표시하고, 사용자가 명시적으로 다시 실행하게 한다.

### A-02 · 화면 탐색/크기 변경이 스킬 변경으로 처리됨 — P1 · 코드

- `skill-tree.js:267-276`의 `renderAll()`은 투자값 변경 여부와 무관하게 저장하고 `toram:skill-investments-changed`를 발생시킨다.
- 트리 이동, 카테고리 이동, 1/5/10 증감 단위 변경도 모두 `renderAll()`을 호출한다.
- `skill-tree.js:284-286`은 창 크기 변경에도 `renderAll()`을 호출한다.
- `combo-ui.js:338`은 이 이벤트를 받으면 사용자가 적용한 계산 기준 타격을 무효화하고 콤보를 다시 렌더링한다.
- 저장소도 같은 이벤트를 자동 저장 신호로 받는다.

**영향:** 사용자가 값을 바꾸지 않고 스킬 트리를 둘러보거나 창 크기만 바꿔도 일회성 계산 기준이 사라지고 상태가 변경된 것처럼 처리된다.

**재구성:** `renderAll()`과 `commitInvestmentChange()`를 분리한다. 실제 레벨 증가·감소·초기화·불러오기 때만 변경 이벤트를 발행하고, 트리 선택·증감 단위·resize는 UI 상태 이벤트만 사용한다.

### A-03 · 최적화 요구조건이 숨은 고정 정책임 — P1 · 코드

`build-evaluator.js:9`의 기본값은 다음과 같다.

| 요구조건 | 기본값 |
|---|---:|
| 단거리 최대 HP | 10,000 |
| 원거리 최대 HP | 제한 없음 |
| 최대 MP | 2,000, `godspeedWieldLevel` 10이면 2,300 |
| 듀얼 적용 전 AMPR | 100, 맥시마이저 10이면 0 |
| 평타 크리티컬 | 100 |
| ASPD | 1,000 |

엔진은 override를 받을 수 있지만 일반 계산 흐름과 UI는 이를 전달하지 않는다. 따라서 사용자는 “딜만 최대화”, HP 20,000, AMPR 무제한 같은 목적을 설정할 수 없고, 추천이 탈락한 이유도 실행 전에는 알기 어렵다.

**재구성:** 장비와 결과 사이에 `최적화 조건` 단계를 추가한다. 각 조건은 활성 체크 + 수치 입력으로 만들고, 직업/스킬 기반 추천 기본값은 “권장값 적용”으로만 제공한다. 실행 전 요약과 저장 문서에 함께 남긴다.

### A-04 · 추천 제외 목록이 저장되지 않음 — P1 · 코드

- 제외 목록은 `crysta-ui.js:1`의 모듈 전역 객체로 시작하며 기본적으로 `오로로 콜론`을 제외한다.
- D4 컴파일 시에는 이 값을 사용하지만 `build-draft-store.js`의 `BuildDraft`와 `settings-repository.js` 저장 문서에는 포함되지 않는다.

**영향:** 동일한 저장 파일을 다른 기기나 새 세션에서 열었을 때 후보 공간이 달라질 수 있으므로 최적화 결과 재현성이 깨진다.

**재구성:** 제외 목록을 `OptimizationPreferences`로 명명해 저장하고, 기본 제외 항목은 화면에서 명시한다. 기존 schema v2는 migration을 두고 버전을 올린다.

### A-05 · 선택 가능하지만 계산되지 않는 옵션을 구분하지 않음 — P2 · 코드/UI

- `crysta-ui.js:227`의 긴 옵션 목록에는 방어, 회복, 추격 등 다양한 스탯이 노출된다.
- `stat-registry.js:7,13`은 일부를 `notModeled`로 보존하며, `d4-global-optimizer.js:31`은 이를 최적화 차원에서 제외한다.
- 테스트는 미모델링 키가 유실되지 않는지를 검증하지만, UI는 “입력은 저장되지만 현재 결과에는 반영되지 않음”을 표시하지 않는다.

**영향:** 사용자는 입력이 계산됐다고 오해할 수 있다.

**재구성:** 옵션 선택기를 `계산 반영 / 저장만 지원 / 향후 지원`으로 그룹화하고, 미모델링 항목 선택 시 행 안에 상태를 표시한다. 최적화 전 진단에도 목록을 노출한다.

### A-06 · 스킬 감소가 우클릭에 숨겨짐 — P2 · 재현/코드

- 스킬 노드는 화면과 접근성 트리에서 일반 버튼 하나로만 보인다.
- 좌클릭은 증가하고 감소는 `skill-tree.js:228`의 `contextmenu`에만 연결된다.
- 터치와 키보드 사용자는 감소 조작을 발견하거나 실행하기 어렵다.
- 총 포인트 초과 투자 허용 이유도 `title` 속성 안에만 있고, 스타젬 투자와 일반 투자가 분리되지 않는다.

**재구성:** 선택한 스킬의 상세 패널에 `− / 현재 레벨 / +`를 제공하고 키보드·터치로 동일하게 조작한다. 초과 투자는 막지 않더라도 “가용 포인트 초과”와 스타젬 가정을 화면에 명시한다.

### A-07 · 세팅 대화상자의 포커스 경계가 불완전함 — P2 · 재현/코드

- 대화상자에는 `role="dialog"`, `aria-modal`, ESC/바깥 클릭 닫기가 있다.
- 브라우저 배포본에서는 native 이름 입력이 숨겨져 있는데도 `build-file-storage.js:120`이 숨은 `elements.name`에 초점을 요청했다. 실제 접근성 트리의 포커스는 뒤쪽 세팅 열기 버튼에 남았다.
- 포커스 트랩과 닫은 뒤 실행 버튼으로의 포커스 복귀도 없다.

**재구성:** 환경별 첫 번째 보이는 조작 요소에 초점을 주고, 모달 내부 포커스 순환과 launcher 복귀를 구현한다.

### A-08 · 가져오기 성공 피드백과 내부 스키마 검증이 약함 — P2 · 코드

- `build-file-storage.js:83-89`는 실패만 표시하고 성공 메시지를 설정하지 않는다.
- 웹과 Rust 검증은 최상위 형식과 주요 키 존재를 확인하지만 캐릭터 수치, 장비 슬롯, 콤보 엔트리 같은 내부 구조를 완전하게 검증하지 않는다.
- 숫자 정규화는 잘못된 값을 0으로 바꿀 수 있어 손상된 파일이 명백한 오류 대신 다른 빌드로 조용히 복원될 가능성이 있다.

**재구성:** 공유 JSON Schema 또는 동등 validator를 두고 경로별 오류를 보여준다. 가져오기 전에 요약·경고를 제공하고 성공 후 파일명과 복원 결과를 알린다. 파일 크기 상한도 둔다.

### A-09 · 최고 파라미터 레벨을 사용자가 설정할 수 없음 — P2 · 코드/UI

- 스탯 포인트는 캐릭터 레벨과 공식 최고 레벨을 이용한다.
- 공식 레벨은 번들 값으로 즉시 시작하고 온라인 공지를 비동기로 확인하므로 네트워크 실패 시 낮아지지 않는 방어는 좋다.
- 그러나 실제 계정의 최고 파라미터 레벨이 공식 상한보다 낮은 사용자는 획득하지 않은 훈장 포인트까지 보유한 것으로 표시될 수 있다.

**재구성:** `계정 최고 파라미터 레벨` 입력을 추가하고 기본값만 공식 상한으로 채운다. 포인트 구성(레벨/5레벨 보너스/훈장)을 항상 펼쳐 볼 수 있게 한다.

### A-10 · 콤보 빈 상태를 유지할 수 없고 최대 8칸이 숨은 제약임 — P2 · 코드

- 투자 스킬이 하나라도 있으면 `combo-ui.js:45-50`이 렌더 과정에서 시작 스킬을 자동 추가한다.
- `renderWorkspace()`는 값 변경이 없어도 `save()`로 변경 이벤트를 발생시킨다.
- 최대 엔트리 8은 `combo-ui.js:4`에 고정되며 화면에는 한도 설명이 없다.

**재구성:** 최초 빈 상태에 `첫 스킬 추가` CTA를 두고 자동 삽입을 없앤다. 렌더와 저장을 분리하고, 8칸 한도 및 현재 미지원 태그/전투 이벤트를 명시한다.

### A-11 · 계산 시간과 목표 수준을 사용자가 선택할 수 없음 — P2 · 코드/UI

- 초기 D4 시간은 UI와 native 서비스 모두 30초로 고정되어 있다.
- 실행 중 취소, native bounded 결과의 계속 계산·일시정지는 제공되어 좋은 편이다.
- 그러나 사용자는 빠른 탐색, 30초, 충분히 증명할 때까지 같은 실행 정책을 사전에 선택할 수 없다.

**재구성:** 실행 버튼 옆에 `빠른 추천 / 30초 / 정확해까지 계속` 모드를 제공하고, 각 모드의 의미를 하한·상한·보장 오차 용어와 함께 설명한다.

### A-12 · 덮어쓰기가 원자적이지 않음 — P2 · 코드

`settings_repository.rs:206-216`은 기존 파일을 먼저 truncate한 뒤 내용을 쓴다. 쓰기 도중 프로세스 종료나 디스크 오류가 발생하면 기존 저장본도 손상될 수 있다.

**재구성:** 같은 디렉터리의 임시 파일에 쓰고 flush/sync한 후 교체한다. Windows 교체 동작을 포함한 실패 복구 테스트를 추가한다.

### A-13 · 소스 버전·공개 릴리스·과거 계획의 상태 표현이 혼재함 — P3 · 코드/문서

- 패키지·Cargo·Tauri 설정은 모두 소스 버전 0.6.3이다.
- `current-development-handoff.md`는 공개된 0.6.2와 배포 보류 중인 로컬 0.6.3을 함께 기록한다. 상단의 “현재 개발 버전”만 보면 소스 버전과 혼동하기 쉽다.
- `d4-exact-optimization-plan.md` 상단은 당시 N0~N6 미완료 상태를 유지하지만 최신 handoff와 native 코드·테스트는 완료 상태를 가리킨다. 과거 계획 기록과 현재 요약의 경계가 눈에 띄지 않는다.

**재구성:** `소스 버전`, `최신 공개 버전`, `배포 보류 여부`를 별도 필드로 둔다. 릴리스 시 버전·handoff·D4 계획 상태를 함께 검사하고 과거 계획 헤더에는 최신 상태 링크를 눈에 띄게 둔다.

### A-14 · 기능 경계는 생겼지만 런타임은 전역 로드 순서에 민감함 — P3 · 코드

- TypeScript 계약, application/port, UI registry는 좋은 경계다.
- 실제 앱은 `legacy-script-manifest.mjs`의 긴 순차 목록과 `window.*` 전역에 의존한다.
- `application-use-cases.js`는 동기 계산 동안 전역 `ToramCalculationInputScope`를 임시 교체한다. 현재 동기 흐름에서는 복구되지만 내부가 비동기/재진입 구조로 바뀌면 요청 간 간섭 위험이 있다.

**재구성:** 데이터 → domain → application → adapter → UI 순으로 ES module 전환을 계속하고, 계산 커널에는 입력을 인자로 직접 전달한다. 전환 기간에는 manifest 순서 검증을 유지한다.

### A-15 · 초기 탭 재배치 전 전체 문서가 잠깐 노출될 수 있음 — P3 · 재현/코드

초기 HTML은 모든 섹션을 한 문서에 두고, 로드 후 `tabs.js`가 DOM을 여섯 탭으로 이동시킨다. 로컬 첫 로드에서 재배치 전 상태가 짧게 관찰됐다. 저사양 환경이나 로딩 실패에서는 더 길게 노출될 수 있다.

**재구성:** 초기 HTML 자체를 탭 패널 구조로 두거나 앱 준비 전 최소 shell만 표시하고, 초기화 성공/실패 상태를 명시한다.

### A-16 · 사용할 수 없는 버프가 “왜 없는지” 보이지 않음 — P3 · 코드/UI

버프 탭은 습득했고 현재 장비 조건에 맞는 액티브 버프만 보여준다. 이는 목록을 줄이지만, 습득했어도 호환되지 않는 버프가 사라져 사용자는 누락 이유를 알기 어렵다. 활성 상태도 주로 파란색/회색에 의존한다.

**재구성:** `사용 가능 / 조건 불충족` 두 그룹으로 보여주고 비활성 카드에 필요한 무기·조건을 적는다. 카드에는 색 외에 `적용 중/미적용` 텍스트를 표시한다.

## 6. UI 재구성 제안

기능을 늘리기보다 현재 기능의 의미를 드러내는 순서로 재구성한다.

### 상단 공통 상태

- 현재 세팅 이름, 저장 여부, 계산 결과의 입력 시점, 실행 엔진(`Native`/`Web Worker`)을 한 줄로 표시한다.
- 전체 입력 오류와 “계산에는 미반영되는 옵션”을 탭별 개수로 표시한다.

### 입력 탭

1. `캐릭터/타겟`: 현재 스테이터스 탭에 계정 최고 파라미터 레벨과 포인트 구성 추가.
2. `장비`: 옵션 검색·그룹·계산 지원 상태, 크리스타와 추천 제외 목록 유지.
3. `스킬/버프`: 스킬 상세 패널에 ± 조작, 조건 불충족 버프를 이유와 함께 표시.
4. `콤보`: 빈 상태를 허용하고 지원 태그·최대 길이·계산 기준 타격을 명시.
5. `최적화 조건`: HP/MP/AMPR/크리티컬/ASPD 활성화와 값, 실행 시간/정확성 모드.

### 실행과 결과

- 항상 보이는 `현재 세팅 계산`과 `크리스타 최적화`를 분리한다.
- 결과 탭 진입은 부작용 없이 기존 결과를 보여준다.
- 결과에는 입력 snapshot 요약, 적용 요구조건, 제외목록, 엔진, 상태(exact/bounded), gap을 함께 보여준다.
- 추천 적용 전 변경 항목을 검토하고 적용 후에는 “입력 변경으로 결과가 오래됨” 상태로 전환한다.

## 7. 권장 구현 순서

1. A-02 렌더/변경 이벤트 분리와 회귀 테스트.
2. A-01 결과 탐색/실행 분리와 stale result 상태.
3. `OptimizationPreferences` 계약 도입: 요구조건, 제외목록, 시간 모드 저장 및 schema migration.
4. A-05 지원 상태 표시와 입력 진단.
5. 스킬 ± 조작, 모달 포커스, 버프 불충족 이유 등 접근성 개선.
6. 깊은 저장 schema 검증과 원자적 덮어쓰기.
7. 문서 버전·D4 상태 드리프트 검사와 레거시 전역 모듈의 점진 전환.
