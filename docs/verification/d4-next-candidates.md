# 제약 상한 강화 이후 개선 후보 탐색

2026-09-26. Native/checkpoint v8의 제품 소스를 읽고 두 격리 실험을 수행했다. 이번 작업에서 제품 알고리즘은 수정하지 않았다.

후속 구현: 1번 계산 벡터 분리의 제품 적용·검증 기록은 `d4-stat-projection.md`에 있다. 아래 수치는 9월 26일의 후보 탐색 실험 기록이다.

## 조사와 실험

### HP 목표 비활성 시 HP 산출 생략

루브닐·유틸리티 충돌 입력의 HP 목표는 null이지만 점수 전용 평가도 HP를 산출한다. target의 복사본에서 준비된 평가 계획에 실험용 flag를 두고 HP 산출식만 생략했다. raw summary는 유지했다.

조사 과정에서 `totalVIT`가 스킬 상수·배율에도 사용됨을 확인했다. 최초 실험 패치가 VIT의 변수 범위를 HP 분기로 옮겨 컴파일에 실패했으며, VIT를 공통 계산에 보존하고 HP 산출식만 생략하도록 수정했다. HP 목표가 없다는 이유로 VIT 계산 전체를 없애면 안 된다.

입력별 각 변형 2회 결과:

| 입력 | 기준 | HP 생략 |
| --- | --- | --- |
| 루브닐 | 6.702 / 6.519초 | 6.511 / 6.655초 |
| 유틸리티 충돌 | 4.036 / 4.090초 | 4.010 / 4.071초 |

반복 범위가 겹치며 평균 차이는 약 0.4~0.6%다. 다음 구현 우선순위에서 낮춘다. 근거: `d4-disabled-hp-probe-measurements.json`.

### 탐색 평가에서 읽지 않는 옵션의 합산 비용

`NativeStats`는 36개 좌표를 조밀 배열로, 나머지를 BTreeMap으로 저장한다. 후보 패키지는 저항·드롭률 등 원본 옵션도 보유한다. 작은 박스 열거는 이 전체 패키지를 매 단계 복사·합산한다. 트리 envelope는 modeledKeys를 이용하지만 완성 조합의 합산 데이터가 같은 범위로 제한되는 것은 아니다.

현재 Native 평가기가 읽는 36개 배열 좌표와 MOTIONSPEED를 제외한 좌표 수를 조사했다:

| 입력 | 패키지 수 | 전체 옵션 항목 | 평가에서 읽지 않는 항목 | 해당 항목을 가진 패키지 |
| --- | ---: | ---: | ---: | ---: |
| 루브닐 | 4150 | 31825 | 8820 | 3781 |
| 듀얼 | 3531 | 27080 | 7736 | 3236 |
| 유틸리티 충돌 | 1788 | 8688 | 0 | 0 |

격리 입력에서 이 37개 계산 좌표만 남겨 같은 기준 바이너리에 전달했다. 모든 트리 modeledKeys가 보존되는지 검사하고 원본 입력 SHA-256과 실제 실행 입력 SHA-256을 구분해 저장했다. 이 실험은 **제품용 구현이 아니다**. 입력의 옵션을 제거하므로 반환 statDelta도 축소되며 제품의 원본 옵션 표시·적용 계약을 그대로 만족하지 않는다.

제품 구현은 원본 패키지를 유지하고 별도의 탐색용 계산 벡터를 준비해야 한다. 최종 statDelta는 원본 패키지로 복원해야 한다. 단순히 modeledKeys로만 거르는 방식도 금지한다. 해당 목록에 없는 유틸리티나 조건 계산 의존성이 있을 수 있다.

projection 12회 결과(`d4-stat-projection-probe-measurements.json`):

| 입력 | 원본 입력 | 계산 좌표만 전달 | 해석 |
| --- | --- | --- | --- |
| 루브닐 | 6.131 / 6.206초 | 5.651 / 5.516초 | 평균 약 9.5% 단축 |
| 듀얼 | 13.847 / 13.719초 | 9.606 / 9.809초 | 평균 약 29.6% 단축 |
| 유틸리티 충돌 | 3.864 / 4.165초 | 3.877 / 3.861초 | 제거할 항목이 없어 두 실행 입력이 동일하다. 차이는 실행 변동이며 개선으로 보지 않는다. |

모두 exact이며 입력별 최적 점수·ID·최종 upper가 일치했다. 듀얼의 열거 조합 수는 동일하며, 원본 옵션 데이터의 복사·합산 비용을 줄이는 방향이 가장 유망하다. 두 반복의 결과로 모든 입력의 개선율/P95를 보장하지 않는다.

## 후속 순서와 승인 Gate

| 우선순위 | 후보 | 상태·검증 방향 |
| --- | --- | --- |
| 1 | 원본 옵션과 탐색용 계산 벡터 분리 | 이번 실험으로 속도 개선을 확인한 후보. 열거·초기해 합산의 불필요한 sparse 복사를 줄이고 원본 저장·출력을 보존한다. evaluator 의존 좌표/동적 stat_total 연결을 명시적으로 검증하고 JS 재평가·음수 옵션·잠금·최적 ID·출력 전체 옵션 보존을 검사해야 한다. |
| 2 | 고정 입력 항의 사전 계산 | 무기 제련·부무기 고정 안정률 항이 여전히 반복 계산됨을 코드로 확인했다. 아직 개별 비용과 실제 속도 이득을 측정하지 않은 후보다. 기존 EvaluationPlan/PreparedEffects와 중복하지 않게 실험한다. |
| 3 | 열거 중 deadline 시각 확인 횟수 조정 | 재귀 진입마다 `Instant::now`를 호출하는 경로를 확인했다. 실제 비용은 미분리다. 취소 플래그·deadline 응답 지연·미완료 공간 복원 Gate가 필요하므로 우선순위를 낮춘다. |
| 보류 | 비활성 HP 산출 생략 | 격리 8회에서 의미 있는 시간 차이를 확인하지 못했다. VIT 대미지 의존성은 유지해야 한다. |

## 재현

```powershell
node tools/probe-d4-disabled-hp.mjs build
node tools/probe-d4-disabled-hp.mjs run
node tools/probe-d4-disabled-hp.mjs projection
```

도구는 현재 제품 소스 5개를 `target/disabled-hp-probe/crate`로 복사해 control/skip-hp 바이너리를 만든다. projection은 같은 control 바이너리에 원본/계산 좌표만 남긴 입력을 번갈아 전달한다. 16작업자, 120초 예산, 순차 새 프로세스, 빌드/다른 테스트와 계측을 겹치지 않았다. JS 후보 준비·UI/IPC는 제외한다. 소스 해시가 달라지면 재빌드를 요구한다.

최종 점수·최적 ID·최종 상한을 대조하며, 전체 입력에 대한 독립 JS 완전 탐색이나 출력 statDelta의 동치를 새로 증명한 것은 아니다. 제품 도입 전에 별도 정확성 Gate가 필요하다. 과거 날짜의 실행 시간과 직접 개선율을 계산하지 않는다.

계측 복사본의 `cargo test --offline --release --manifest-path src-tauri/target/disabled-hp-probe/crate/Cargo.toml --bin d4_native_parallel` 49/49, 도구 문법 검사, 제품 소스 SHA-256 불변 확인, AI 문서 감사·diff 검사 통과. 기존 제품 R0/R9/S1·설치본 E2E는 이번 탐색 작업에서 재실행하지 않았다. 현재 제품의 제약 추가 분할 구현 기록은 `d4-constraint-lookahead.md`에 있다.
