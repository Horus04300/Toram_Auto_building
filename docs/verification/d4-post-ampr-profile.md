# AMPR 개선 이후 병목 재측정

2026-09-26. 제품 소스는 변경하지 않고 Native v7의 복사본에 계측을 추가했다. 이전의 부분 조합 검사와 AMPR 중복 계산 제거가 반영된 상태다.

## 방법

- 기존 준비 입력 revenir/dual/utility-tight, 16작업자, 입력당 control/profile 각 2회, 총 12회 순차 새 프로세스 실행. 빌드·회귀 검사와 성능 실행을 겹치지 않았다. JS 후보 준비·UI/IPC는 제외한다.
- control에도 초당 진행 snapshot이 있다. profile에는 기존 evaluator/boxStats/작업/큐 구간 외에 **utilityStage**(VIT·HP부터 ASPD 목표 판정까지), **damageStage**(통과 이후 대미지 계산)를 추가했다. 제품 파일을 수정하지 않고 target의 격리 crate에 삽입한다.
- evaluator/boxStats/두 세부 단계는 1024회 중 1회 시간 표본, worker/pool/큐 구간은 전체 시간을 잰다. evaluator는 두 단계 및 계측 오버헤드를 포함한다. 각 표본 집합이 다르고 중첩되므로 추정 시간을 합산하거나 정확한 CPU 점유율로 해석하지 않는다.
- profile/control 시간차는 루브닐 +19.8%/-1.5%, 듀얼 +0.5%/+2.9%, 충돌 +2.7%/+0.4%였다. 특히 루브닐 대조 실행도 8.60~10.21초로 변동한다. 세부 계측은 방향 판단용이며 시간 비교는 control 기준으로 보고한다. 지난 날짜의 13~14초 듀얼 결과와 이번 결과를 제품 회귀로 단정하지 않는다.

## 다음 개선 순서

| 순서 | 대상 | 이번 근거와 구체 실험 |
| --- | --- | --- |
| 1 — 기존 후보 3 | 큰 박스의 제약 상한 강화 | 루브닐은 약 5715만 boxStats 호출과 약 294만 대기 후보가 남고 큐 pop에 약 35%를 쓴다. 작은 박스 개선만으로 줄지 않은 공간이다. 제약 여유가 적은 큰 박스에만 추가 안전 분할을 적용해 제거율/추가 평가 비용을 비교한다. 모든 박스에 개별 256회 검사를 넣지 않는다. |
| 2 | 요구하지 않는 유틸리티 계산 생략 | 루브닐과 충돌 입력의 HP 목표는 null인데 현재 점수 전용 평가도 VIT·HP를 계산한다. 해당 계산과 결과 의존성을 먼저 분리해 HP 목표 비활성 시 생략하는 소규모 실험이 가능하다. 이번 구간 계측은 HP 단독 비용을 분리하지 않았으므로 절감 폭은 미확정이다. |
| 3 | 듀얼 평가의 고정 항 사전 계산 | 듀얼은 약 1.10억 평가가 거의 모두 대미지까지 진행한다. 제약 삭제보다 평가당 비용 감소가 적합하다. 고정 무기 제련 항 등 아직 반복 계산하는 입력 상수를 준비 단계로 옮기는 A/B를 검토한다. 이미 적용한 무기/공격유형 경로 준비와 AMPR 중복 제거를 다시 구현하지 않는다. |

첫 후보의 성공 조건은 최적 점수·동점 ID/안전 상한 보존과 평가·대기 후보·완료 시간의 동시 감소다. 표본 타이머의 비중만으로 특정 구현의 이득을 보증하지 않는다. 이번에는 후보 구현을 진행하지 않았다.

## 재현·검증

```powershell
node tools/profile-d4-slow-inputs.mjs build
$env:D4_PROFILE_FIXTURES='revenir,dual,utility-tight'
$env:D4_PROFILE_THREADS='16'
$env:D4_PROFILE_REPEATS='2'
$env:D4_PROFILE_BUDGET='120000'
$env:D4_PROFILE_REPORT='post-ampr-complete.json'
node tools/profile-d4-slow-inputs.mjs run
$env:D4_SUMMARY_EXPERIMENT='post-ampr'
node tools/summarize-d4-post-utility-profile.mjs
```

- 집계기는 소스 SHA-256, 12회 exact 점수·ID·최종 upper 일치 및 진행 구간을 검사한다. `certificateIssues`는 **0건**이다. 전체 입력의 독립 완전 탐색을 새로 실행한 것은 아니다.
- 계측 복사본 Rust release 테스트 48/48 통과. 두 계측 도구 `node --check` 통과. 제품 변경이 없어 앱 R0/R9/S1·실제 UI/저장 E2E는 재실행하지 않았다.
- `d4-post-ampr-profile-measurements.json`에 소스/입력 해시·최종 결과·구간 집계·메모리·CPU·진행 trace를 보존한다. 이전 기록을 덮어쓰지 않았다.
- 이전 구현/검증은 `d4-ampr-evaluation.md`, 부분 조합 검사는 `d4-partial-utility-pruning.md`를 참조한다.
