# 전체 옵션의 공동 공급량 상한

2026-10-11. Native v19 / 평가 v4. 현재 제품 상태는 [handoff](../handoff/current-development-handoff.md), 52키·14쌍·확장 묶음의 목록은 [inventory](crysta-joint-supply-inventory.md)를 따른다. 현재 데이터 출현 여부를 구현 조건으로 쓰지 않았다.

## 구현

`src-tauri/src/optimization/joint_supply.rs`가 Native 계산 그래프의 affine 외향 상한을 만든다. 기본 스탯 쌍→무기별 기초값→공격/속도/HP·MP·AMPR→치명타/안정률/관통→최종 배율을 연결한다. 단일 탐색·독립 병렬·shared session·checkpoint 재구성의 공통 `evaluate_box`에서 사용한다.

범위에는 ATK%/ATK+/물리관통, 대칭 마법 묶음, 무기/스탯/듀얼/컨버전, 14개 %·+ 쌍, MP→AMPR, ASPD→행동속도, 치명타×크뎀, 발도 변환·거리·속성·대미지·total 스탯 스킬 계수가 모두 포함된다. 현재 없는 stat-up 10키와 속성 플래그 2키를 Native 평가에도 연결했다. stat-up과 속성 INT 보너스는 기존 식의 **순수 기본 스탯**을 읽는다.

CSPD/영창 감소도 Native 파생 평가와 상한을 지원한다. 목적은 기존 선택 공격의 기대 대미지이고 요구조건은 기존 5개다. CSPD를 새 목표나 DPS 배율로 쓰지 않는다. AMPR%는 raw 표시에는 적용하지만 사용자 정책에 따라 목표에서 제외한다. 계산식이 없는 51개 보존 옵션으로 새로운 목적식을 추정하지 않는다.

ASPD에서는 먼저 STR/DEX/AGI/INT의 %·flat을 합산해 최종 스탯을 만들고, 무기 계수와 레벨·갑옷으로 기초값을 만든 뒤 ASPD %·flat을 적용한다. 기초값과 비율이 동시에 변하는 곱을 모델링하므로 후보 전체에 고정된 `% 대 +` 교환비를 적용하지 않는다.

## 상한이 안전한 이유

각 패키지의 실제 52좌표 벡터를 사용한다. 전역적으로 유효한 선형 상한 `U(s)=c+a·s`에 대해, 상자 안의 최고 지지값은 다음과 같다.

```text
upper(box) = c + outward_error
           + Σgroup max(package in that child subtree, a·package.stats)
```

같은 후보에서 나온 옵션을 먼저 하나의 내적으로 묶는다. 서로 다른 후보의 ATK%, ATK+, 관통 최고치를 실제 동시 공급량으로 취급하지 않는다. 부모에서 유효한 평면은 자식에서도 유효하며 자식의 지지값 캐시를 사용한다. 대규모 pair frontier를 물질화하거나 실제 후보를 삭제하지 않는다.

변동 기초값 `x`와 변동 비율 `y`의 곱에는 `[lx,ux]`, `[ly,uy]`에서 유효한 McCormick 평면을 사용한다.

```text
xy ≤ ux·y + ly·x − ux·ly
xy ≤ lx·y + uy·x − lx·uy
xy ≥ lx·y + ly·x − lx·ly
xy ≥ ux·y + uy·x − ux·uy
```

계수의 부호에 따라 이미 인증한 피연산자의 상/하 평면을 선택한다. 변수 사이의 상관이 있어도 이 부등식은 유효하다. root에서 선택한 평면을 자식에도 유지하며 실제 패키지의 최대 내적을 캐시한다.

`x−1 ≤ floor(x) ≤ x`를 원래 내림 위치에 적용한다. 후보별로 내림한 공급량을 합하지 않는다. max/min·포화는 외향 평면, signed trunc와 불연속 조건은 가능한 분기 양쪽을 포함한다. STR/AGI 기초 크뎀은 동치인 max 표현으로, 크뎀 300 초과 감쇠와 CSPD 1,000 구간은 연속적인 상한으로 표현한다. 수치 오차 여유를 전파하며 원시 옵션을 반올림하지 않는다.

각 유효 목표 `G≥R`, 가중치 `λ≥0`에 대해 `D ≤ U_D+λU_G−λR`도 안전하다. HP/MP/AMPR/CRIT/ASPD와 공격의 같은 패키지 공급량을 이 방향에 반영한다. 이미 전체 공간에서 충족되는 목표나 상수 목표 평면은 추가해도 대미지 평면을 개선할 수 없어 생략한다. 방향 선택/예산은 상한의 강도와 비용을 정하며 게임 수치가 아니다.

기존 좌표 envelope이 안전한 문맥에서는 공통 평면으로 얻은 **raw 대미지·최종 크뎀·안정률·속성·스킬 계수·거리 배율의 인증 상한**을 기존 evaluator 단계에 적용한다. signed 배율, 음수 기초값, stat-up/속성 후보, Dual Bringer 등의 안전 조건이 충족되지 않으면 기존 envelope 가지치기를 사용하지 않고 전체 계산 그래프의 상한을 사용한다. HP의 음수 비율은 기초 HP가 비음수이고 최대 비율이 양수일 때 양수 최고값으로 안전하게 덮을 수 있다.

고정 상한은 후보를 순회하지 않는다. 준비 중 만든 지원값 캐시는 immutable Arc로 공유해 worker마다 복제하지 않는다. 최대 27방향이며 CSPD/영창 표시 평면을 매 노드의 목표 검사에 넣지 않는다.

유한 수치 범위/산술 예산을 벗어나 준비가 불가능하면 해당 선택적 상한을 무한대로 열고 exact 평가를 유지한다. 그때 안전성이 확인되지 않은 기존 envelope로 되돌아가지 않는다. checkpoint v19는 no-incumbent와 무한 상한 sentinel을 JSON 문자열로 보존하며 v18 이하 checkpoint를 거부한다. 앱 저장 schema·출시 버전은 유지했다.

## 실제 실행 기록

측정 원본은 `crysta-joint-supply-bound-measurements.json`이다. 같은 JS와 실제 입력을 컴파일·준비하고 전후 Native 실행파일을 새 프로세스로 순차 실행한다. 방문·평가 수는 **exact 증명 완료까지** 비교하며, 기존 evaluations 카운터를 전체 CPU 명령 수나 낭비율로 해석하지 않는다. 결과 복원 후 JS로 요구조건·점수·raw 옵션을 다시 확인한다.

실제 잠금 해제의 전체 평균은 13.42%, Native 평균은 31.75% 감소했다. 과거 작은 회귀는 방문/평가가 줄어도 추가 상한 비용으로 전체 평균 8~11ms(각 1.33%/1.31%) 늘었다. 단일 잠금 루브닐 P95도 806.84→815.96ms이므로 평균의 작은 이득을 모든 실행의 속도 개선으로 해석하지 않는다. 전역적인 무퇴행·모든 무기의 동일 개선율을 주장하지 않는다. 이번 채택 근거는 현재 세 실제 입력의 연산량 감소와 동일 결과, 실제 잠금 해제의 시간/메모리 이득이다.

별도의 1-worker 과정 trace는 제한 시간 없이 최대 10,000 batch를 실행했다. control/계측판이 같은 점수·ID·상한·방문·평가·열거 수로 끝났고 사건 카운터가 일치했다. 초기 점수 1,891,701.18, root 상한 3,338,497.74에서 시작해 8,574 batch에 exact 1,910,660.94를 증명했다. 방문 700,696·평가 2,873,600·완성 조합 평가 159,147, 관측 최대 미해결 상자 117,056이다.

첫 살아남은 자식의 로그는 같은 패키지 지지값에서 raw 대미지 상한 약 7,679.98, 크뎀 336.04, 안정률 100, 속성 71, 스킬 배율 16.2, 거리 89를 얻고 기존 envelope과 함께 자식 점수 상한 2,584,053.72를 만든 과정을 담는다. 중복 bound 평가 60회와 임시 초기해 순위 계산도 별도로 기록했다. `seedImproved`는 전역 incumbent 갱신 횟수가 아니다.

진입점은 `node tools/benchmarks/trace-crysta-search.mjs build` 후 `run --threads 1 --max-batches 10000`이다. 원본 이벤트/배치 로그는 `src-tauri/target/search-trace/`, 공유 가능한 요약과 소스 hash는 측정 원본에 보존한다. 계측판 시간을 제품 시간으로 보고하지 않는다.

cold 실행 결과·현재 소스 hash·입력·trace를 다시 검증해 요약하는 명령은 `node tools/verification/summarize-crysta-joint-supply.mjs`다. 비교 실행의 임시 driver/원본 100회 결과는 `src-tauri/target/joint-supply/`에 있으며 영구 측정 JSON에도 모든 실행을 보존했다.

현재 저장 검방·실제 평타 외의 무기 성능, 앱 UI/WebView 및 설치/업그레이드는 이번 실행의 범위 밖이다. 경계를 넘는 상자의 외향 완화는 느슨할 수 있으므로 모든 입력에서 동일한 절감률을 보장하지 않는다.
