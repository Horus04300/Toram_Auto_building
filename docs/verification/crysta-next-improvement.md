## 실험한 상한 계산

공격 좌표는 3개이며 각 좌표의 기존 15개 지지 방향을 모두 유지했다. 후보·필요량·가중치·분할·상한 강도를 줄이지 않았다.

- floor: 지지값별 내림 15회를 좌표별 마지막 내림 1회로 이동한다.
- direct: 위 변경에 더해 임시 지지값 배열을 생성하지 않고 직접 누적한다.
- indexed: 고정 4개 장비의 주소를 한 번 읽고 배열 변환·중첩 iterator 처리를 줄인다. 공격 좌표가 전부 고정이면 조임 작업을 생략한다.
- unrolled: 위 변경에 더해 고정된 15개 방향의 계산을 직접 전개하여 loop/index 처리 비용을 줄인다.

각 지지값 x와 양수 좌표 단위 u에 대해 min_i(floor(x_i) * u) = floor(min_i x_i) * u이므로 마지막 내림으로 옮겨도 수치 상한은 같다. 기존 원시 좌표 상한과 min을 취하는 계약은 유지한다. 지원 좌표는 유한 외향 정수, k는 1·2·4이며 u는 양수 2의 거듭제곱이다. 원래 값보다 작을 때만 같은 좌표를 갱신한다. 실험 audit은 수치 비교뿐 아니라 실제 삽입값의 bit도 대조했다.

입력의 무기·스킬·장비 이름을 조건으로 선택하지 않는다. 다만 결합 공격 상한이 활성인 입력에서 효과를 낼 수 있는 후보다. 유효한 제약이 없어 해당 상한이 비활성인 입력에는 이 개선 지점이 적용되지 않는다. 실제 듀얼 입력은 측정하지 않았다.

## 동치 확인과 판단

- 분리된 prototype의 기존 Rust 테스트 76개 PASS. oracle·상한 coverage·소수/큰 값·음수 기본 스탯·1~64 threads·checkpoint/cancel/deadline Gate를 포함한다.
- 별도 audit 실행은 각 조임마다 기존 함수를 다시 계산하여 3개 공격 좌표의 존재 여부와 f64 bit를 비교했다. 실제 루브닐 4,112,812개, 평타 3,993,194개 상자에서 모두 일치했다. 최종 점수·전체 조합도 기준 결과와 같았다. audit 시간은 성능 평균에 섞지 않았다.
- 평가의 정수/십진 fallback 분리와 다른 정수 나눗셈 경로도 단발 탐색했으나 뚜렷한 이득을 확인하지 못해 반복 Gate·제품 반영을 진행하지 않았다. 소스와 측정은 원본 보고서에 실패 후보로 구분한다.
- 제품 소스 6개는 조사 시작 시의 hash와 그대로 일치한다. 분리 실험 도중 재빌드된 개발용 headless 산출물은 원래 제품 manifest로 재빌드했다. 앱 실행 파일·게임 계산식·캐시/continuation v13은 변경하지 않았다.

다음 구현 우선 후보는 공격 상한 계산의 직접 처리다. 개발 실행에서 반복 이득이 확인됐지만, 제품 반영 전에는 방향 목록의 향후 변경에도 누락이 없도록 생성/검사 방식을 정리하고 최종 production 코드로 회귀·성능 Gate를 실행해야 한다. 배포 빌드의 큰 단축은 이번 조사에서 확보하지 못했다.
